# ADR-001: Unified Severity Schema

## Status
Accepted

## Context
The hackathon build used two incompatible severity schemas across layers:
- Frontend: `critical | severe | moderate | routine`
- Backend training data and cloud function: `routine | moderate | urgent | emergent`

The two subsystems never communicated, so the mismatch was never surfaced during the demo.
For v2.0, a single schema must be chosen and enforced across every layer.

## Decision
Adopt `routine | moderate | urgent | emergent` as the canonical four-class schema for all layers.

Rationale:
- Aligns with standard emergency triage terminology (ESI, CTAS)
- Already used in the backend training data and cloud function
- `critical` and `severe` are colloquial, not clinical — replacing with `urgent` and `emergent` reads correctly to health tech reviewers

## Consequences
- `critical` and `severe` are retired — do not reintroduce
- Frontend severity-colored markers must be updated to the new labels
- The fine-tuned training dataset already uses this schema — no relabeling needed
- `shared/types.ts` is the enforcement point — TypeScript will catch any misuse at compile time
